# 票房数据字典

## 输入契约

一次发布提交以规定文件名标识的五份 CSV。列顺序可变，列名匹配区分大小写。先解码 UTF-8（允许 BOM），失败改用 GB18030。CSV 原值保留字段数组及物理起止行。重复表头和空行单独计数。缺列、截断引号、无法解码、中途超限时整批失败。单条多列或少列按 `COLUMN_COUNT` 隔离。

| 文件 | 字段及定义 |
|---|---|
| `tickets.csv` | `ticket` 字符串票码，`paid_at` 收款时刻，`amount` 金额，`unit` 元或分，`status` 仅 `paid` 可入账，`note` 可空说明 |
| `shows.csv` | `show` 场次键，`title` 演出名，`venue` 场馆，`publication_status` 为 `open` 或 `held`，`opens` 和 `closes` 为核销起止，`cancelled_at` 空串表示正常场次 |
| `rights.csv` | `ticket`、`show` 唯一组合，`weight` 为 1 至 10,000 的整数 |
| `scans.csv` | `scan_id` 核销流水号，`ticket`、`show`、`scanned_at` 入场时刻，`gate` 为闸口名 |
| `refunds.csv` | `refund_id` 退款流水号，`ticket`、`show`、`refunded_at` 退款时刻，`amount`、`unit` 为实际退款请求。整单退款可省略 `show` 列，或在 `show` 留空表示渠道未指明场次 |

编号允许英文、数字、连字符和下划线，最多 64 字符，首位须为英文或数字，前导零保留。字符串前后空格去除。必填字段中的空串、`-`、`N/A`、`NULL`、`未知` 进入隔离。表头为空、文件只有空行有不同错误，表头存在且无数据可用于零权益、零核销或零退款。有效票源和场次均至少一条。

时间输入须是带 `Z` 或数值偏移的 ISO 秒级时间，归一为 UTC，首页显示上海时间。核销时间窗 `[opens, closes)`。核销不得早于收款，停演时刻起不再核销。重复核销先按标准时刻排序，同刻按流水号升序；最早有效票场事件保留。相同业务键的完全相同记录保留最早来源，冲突组全数隔离。票源 `note` 不参与同一业务记录判断。

金额可用全角数字、规范千位分组。元最多两位小数，分只收整数文本。单笔金额须为正，最多 9,999,999,999 分。解析时用 Decimal 转分，其余金额运算使用整数。每份文件的上限保证批次汇总落在 JavaScript 安全整数范围内。

## 发布及冲正

首次发布只把实收分给 `open` 且有有效权益的场次。每份先取整，剩余分按余数降序、场次键升序分配。`remainder` 是分子整除权重和后的整数余数，`rank` 是分发顺序，`extra_cents` 只能为 0 或 1。无合资格权益的票款进入未结余额，保留 `NO_ELIGIBLE_RIGHTS`。

`publication_status` 表示原发布资格。`cancelled_at` 卡住后续核销，并让该场剩余原分账不进入场馆应收。停演场次退款至少在停演和收款之后，时刻相等也合法。退款按时刻和流水号升序逐条试扣，单笔越过剩余限额时整笔隔离、额度保持不动。冲正为负分，显示余额和退款统计为非负分。补报须保留已通过的退款编号、金额和业务事实（含逐场落点），无法保留的修订返回 `REFUND_CHANGED`。

### 整单退款落场

渠道整单退款只回传票码和退款额，`show` 为空。可落场次是这张票在发布时取得原分账的全部场次。只要其中任一场次已停演，且退款时刻不早于停演和收款，整笔退款即可入账。落场按各场原分账金额等比例分摊，取整用最大余数法、余数相同按场次键升序。某场剩余额度不足时，超出部分只在仍有余量的场次间按原分账比例继续分摊，直到整笔落完。

因此每场累计冲正永不超过该场原分账，已演出场馆不会替未演场次承担退款，后段场馆也不会替前段场次承担。单笔超过这张票全部可退余额时整笔隔离为 `REFUND_CAP_EXCEEDED`，额度不动。渠道重试若换了退款单号但票码、退款时刻和金额都相同，视为同一笔退款，只入账一次，其余记为 `REFUND_RETRY`，不重复扣款。处理失败（如补报改写已过账冲正）整批返回 `REFUND_CHANGED`，旧版结果原样保留。

原发布保存票源、场次定义、权益的摘要及其来源行。变化后的原始定义需要使用不同账册编号。核销与退款可追加或修订，返现操作由外部渠道完成。账册保留每次发布的输入快照，不提供跨账册合并。

## 勾稽与凭证

- `净收款 = 实收票款 − 已入账退款 = 场馆应收 + 未结余额`。逐票检查，避免两票串账互相抵消。
- `原分账 = 场馆应收 + 场次未结 + 已入账退款`。差额槽的「账面差额」是原分账减应收，勾稽差异是扣除场次未结和冲正后的剩余值。
- 场馆应收只计正常场次的有效核销。未结包括未核销、停演未退完及未分配票款。
- 待追回是按场馆汇总的、已演出并已结算场次被冲正的部分：这些钱原已算作场馆应收，整单退款冲回后需要向该馆收回；停演或未演场次的冲正只减少未结，不计入待追回。
- 首页「整单退款落场」显示本期每笔整单退款留在哪些场次，以及各场原分账、本次冲正和剩余额度；「各馆净应收与待追回」按场馆显示净应收和待追回金额。
- 源行守恒按逻辑记录计，`逻辑行 = 采信 + 隔离 + 空行 + 表头`。相互冲突的每条原始记录只计一次。
- ZIP 同时保留本次输入、原分账来源和结果 CSV，并新增 `evidence/refund-shares.csv` 记录每笔退款逐场落点与其额度。`manifest.json` 含入参、版本、运行编号、原发布编号、时间、耗时、逐文件 SHA-256、勾稽检查及汇总。JSON 和原始文件逐字保留票码，CSV 复核时请将票码列按文本导入。
- 本期退款凭证可从 `GET /api/evidence/{run_id}/refunds.csv` 单独下载，字段与 `refund-shares.csv` 相同，末列 `remaining_cents` 为该场冲正后的剩余额度。
